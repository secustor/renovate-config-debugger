# 072 — Option docs: say where an option may go, and what the table does not know

Milestone: M19 · Status: in progress

## Summary

`get_option_docs` and `rcd docs` projected 15 of Renovate's ~30 per-option
fields, and the pretty renderer printed fewer still. Two gaps mattered, and
both produced silence rather than a wrong answer — which is worse, because
silence reads as "no data" and gets filled in by guesswork:

1. **Where an option may appear.** The projection forwarded `parents` verbatim
   and rendered `valid under: …` only when it was truthy. 402 of 485 options
   declare no `parents` at all, so for 83% of the table both surfaces said
   nothing — and the two that DO carry `"."` (`enabled`, `fetchChangeLogs`)
   printed it as if it were the name of a parent option.
2. **The glob/negation and templating markers.** `patternMatch` (24 options)
   and `allowNegative` (1) are exactly the facts a reader guesses at, and they
   were dropped on the floor, along with `supportsTemplating` (53), `stage`
   (247), `mergeable` (173), `allowString` (21), `inheritConfigSupport` (11),
   `freeChoice` (7), `requiredIf` (1), `format` (2) and `experimentalIssues`
   (5).

Plus one duplication: `isContainer` was derived at BOTH call sites
(`mcp/server.ts`, `commands/docs.ts`) by asking the index, and the CLI's pretty
branch then dropped it — the exact shape of drift this milestone's projections
convention exists to prevent.

## The proof that `parents`-absence is a statement

This is the load-bearing fact of the whole change, so it is recorded here
rather than re-derived: in the pinned Renovate (44.7.4),
`dist/config/validation.js` builds `optionParents` only from options that
declare `parents` (`:97`), and enforces nesting only for keys present in that
map (`:166`). An option with no `parents` is therefore legal at the top level
AND inside any container object — not "unspecified". That is why
`OptionPlacement` has an explicit `unrestricted` member and why `placement` is
a REQUIRED field: "we didn't say" is unrepresentable.

`"."` is lifted out of the parent list into `placement.topLevel`. It is a
placement fact, not a parent name, and `valid under: ., npm, packageRules` was
actively confusing.

## The version-history ceiling

There is no per-option version history to project. Searched in the pinned
package: no `since`/`addedIn`/`introducedIn`/`versionAdded`/`deprecatedSince`
field anywhere in the option table; no `CHANGELOG` in the renovate package
(`dist/data/changelog-urls.js` is dependency changelog URLs, not Renovate's
own); `renovate-schema.json` carries only `x-renovate-version`; `package.json`
has no build SHA. This is an upstream data gap, not a projection gap.

Three responses, none of them fabrication:

- Every pretty header names the pinned version (`packageRules (array) —
Renovate 44.7.4`), and `--search` counts against it.
- `optionsSourceUrl` is a version-pinned citation
  (`https://www.npmjs.com/package/renovate/v/<version>`). The per-option `url`
  points at docs.renovatebot.com, which serves LATEST and silently drifts from
  the pin, so it cannot be the citation. The github blob URL for
  `lib/config/options/index.ts` would be more precise, but it needs the tag
  shape confirmed against the network; the npm URL is immutable and certainly
  correct.
- The ceiling is stated out loud, once per surface: in `rcd docs --help` and in
  the MCP tool description. A silent gap invites an agent to invent history; a
  named limit does not.

Deliberately NOT added: a `since`/`addedIn` field, even nullable. Always-null
reads as "no data for THIS option" rather than "no data exists", which is a
worse lie than silence.

## What the projection now carries

`OptionDoc` gains `placement`, `isContainer`, `childOptions`, `patternMatch`,
`allowNegative`, `supportsTemplating`, `stage`, `requiredIf`,
`inheritConfigSupport`, `allowString`, `freeChoice`, `format`, `mergeable`,
`experimentalIssueUrls` and `notes`. `OptionIndex.containers` becomes a
`ReadonlyMap<string, readonly string[]>` (parent → the options restricted to
it) instead of a `Set`; `.has()` is the only method any caller used, so the
change is source-compatible.

Rejected, with the evidence, so nobody re-litigates them:

- `env` (93 entries) and `cli` (261) carry no names — every entry is a `false`
  opt-out. There is nothing to surface.
- `autogenerated` (118), `additionalProperties` (10), `replaceLineReturns` (2)
  drive Renovate's docs-site and schema generation; no user-visible behavior.

### Two honesty constraints the renderers must keep

- **`childOptions` is not "everything valid here."** It is the RESTRICTED set —
  the options that named this container in `parents`. Any unrestricted option
  may also appear inside it, and most options are unrestricted. Both renderers
  say so on the line after the list. Getting this wrong replaces one ambiguity
  with a worse one.
- **`requiredIf` is declared but never enforced.** `grep -rl requiredIf dist/`
  hits only the type declarations and the option table itself; the pinned
  validator does not read it. The rendered line carries that caveat, or the
  tool lies.

The prose for a flag lives in ONE place — `PATTERN_MATCHING_NOTE`,
`TEMPLATING_NOTE`, `REQUIRED_IF_NOTE` in the engine, attached to the doc as
`notes` — so the flag is the machine-readable fact and the note is the
sentence, and neither renderer composes its own. `STRING_PATTERN_MATCHING_DOCS_URL`
is shared with `error-translations.ts`, whose `redundant-glob-star` translation
already cites that page.

## Truncation belongs to the renderer

`enabled` declares 129 parents and `managerFilePatterns` 117. The engine keeps
every name (JSON is complete); `packages/cli/src/projections/option-doc.ts`
cuts at 8 plus `(+N more; --format json for all)`, and the app card truncates
the same lists to a fixed width. A pretty renderer that printed `parents`
unbounded produced a wall of text nobody reads.

## The guard

`packages/cli/src/projections/option-doc.test.ts` sweeps every option in the
index and asserts that for each flag set on a doc, the corresponding line is
present in `optionDocLines`. That is what mechanically prevents the failure
mode this milestone fixed — a fact reaching `--format json` and silently never
reaching the reader. `packages/engine/test/option-docs.node.test.ts` adds an
invariant sweep over the whole table (every doc has a placement; restricted
exactly when upstream declares `parents`; `"."` never in `placement.parents`;
`isContainer` exactly when the name is a container key), which is the
regression net for the next Renovate bump.
