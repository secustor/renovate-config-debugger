Mockup 045 — auto-load the org's inherited config

A default-enabled checkbox in the repo-load disclosure (039) probes {{parentOrg}}/renovate-config for org-inherited-config.json on every successful load and fills the inherited-config layer (008). Section 1: where the checkbox lives. Section 2: the three states the auto-loaded layer can land in.

Mockup — static HTML, tokens and geometry copied from packages/app/src/index.css. Nothing is interactive except the disclosure toggles.

1 · The checkbox in the repo-load row

Constraint from 035: the repo-load panel is ONE unwrappable row — inputs shrink, buttons never do, and nothing may orphan Load onto its own line. The checkbox has to respect that.

Now — no way to bring the org's inherited config along

{ "extends": ["config:recommended"] }

1A · Inline in the row (terse label)

Fits the one-row invariant only with a terse label ("org config") — the full sentence would crush the inputs at narrow widths, and a bare two-word label under-explains a default-on network fetch.

Config — renovate.json
{ "extends": ["config:recommended"] }

1B · Its own sub-row (recommended)

A second line inside the same surface: the one-row invariant for inputs + buttons stays untouched, the label can say what actually happens, and the row disappears with the disclosure like everything else (039). Costs one line of transient height only while the form is open.

Config — renovate.json
(renovate-org/renovate-config · org-inherited-config.json)
{ "extends": ["config:recommended"] }

Recommendation: 1B. The label names the fetch it triggers and previews the exact repo/file it will probe (templated live from the typed owner), which a default-on network action owes the user. 1A's terse label survives the row constraint but explains nothing.

2 · The layer after the load

The Advanced zone's existing "Inherited config" section (008) — the probe only fills it, the section itself is unchanged. Three possible states.

2a · Found — layer filled, origin labeled, still editable

Inherited config — org-wide defaults shared across repositories · active

auto-loaded from renovate-org/renovate-config · org-inherited-config.json — editing makes it yours, like a pasted layer.

2b · Not found — quiet note, layer stays empty

Inherited config — org-wide defaults shared across repositories

No org inherited config: renovate-org/renovate-config has no org-inherited-config.json (404). A real run tolerates this too (inheritConfigStrict is off by default).

2c · Found, but the pasted global config disables it

The only case needing a warning: default-on matches the Mend-hosted app (which runs with inheritConfig enabled), so the hint appears solely when a pasted global config EXPLICITLY sets inheritConfig: false.

Inherited config — org-wide defaults shared across repositories · active

auto-loaded from renovate-org/renovate-config · org-inherited-config.json

Your global config sets inheritConfig: false — a run under that global config would not apply this layer.

Sum: 1B for the checkbox; the layer states reuse the 008 section verbatim with one new origin line (badge + source) and the inverted honesty hint from the 045 doc — no new UI surface anywhere else.
