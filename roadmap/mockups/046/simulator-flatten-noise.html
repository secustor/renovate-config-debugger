Mockup 046 — simulator flatten-noise & final-section clarity

Two defects from the 2026-07-26 review of the 044 stepper, both UI-side only (the engine's oracle parity is untouched). Section 1: changedKeys diffs the pre-rules effective config against the post-flatten per-dependency config, so the seven update-type blocks Renovate's flattenUpdates always deletes (major, minor, patch, pin, digest, lockFileMaintenance, replacement) show up as "removed" — no rule removed them. Section 2: the final section claims "Rules changed: 8 keys" while its own stepper opens with "this rule changed nothing — No differences", and the section heading promises a config that is actually hidden behind the disclosure at the bottom.

Mockup — static HTML, tokens and geometry copied from packages/app/src/index.css. Nothing is interactive except the disclosure toggles. Scenario throughout: the screenshot's run — npm react 4.17.20 → 4.17.21, updateType unset, 2 of 714 rules matched, the repo rule sets groupName: "react".

1 · The verdict block's changed-keys list

Fix: flatten the BASE config the same way the engine flattens the final one before diffing (drop the update-type blocks from both sides), so only keys a rule (or a real update-type merge-up) changed survive. A block that genuinely merged up keeps its existing "from the minor block" attribution — that path is unaffected.
