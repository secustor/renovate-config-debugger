Design notes

Palette — nothing new, roles sharpened
verdict green (app --ok) is reserved for the judgment and genuine changes; preset purple and repo blue are the provenance colors the rule chips already use, now doing structural work on the rail; amber (app --warn) marks consumption — the flatten step and its aside, and nothing else.
Type — the modal verb is the display moment
One size up for the verdict sentence (1.25rem, balanced wrap), config values inline in the mono utility face, and the WOULD / WOULD NOT badge as the only display flourish. A negative verdict reads would not in the same grammar — the badge color is the verdict.
Structure — geometry that can't contradict the copy
The old section claimed "8 keys changed" above a step showing "No differences". On the sequence those two facts are one drawing: in 2B, the 024 dot vocabulary carries it — green circle = ran clean (matched, changed nothing), amber diamond = changed things, with the delta in the chip's count slot. Step numbering survives because merge order is real information — later stops win.
Motion — one orchestrated moment
The 2A rail assembles left-to-right once on result load (~0.5s), miming accumulation; nothing else animates, and prefers-reduced-motion turns it off. 2B keeps the Pipeline timeline's stillness — chips appear with the result, like the tab it echoes.
Implementation
UI-only, as before: changedKeys drops the update-type blocks from its base copy; SimVerdictBlock becomes the card (band / ledger / foot). For 2B the sequence is a sibling of StageTimeline reusing the .stage-timeline/.stage-chip/.stage-sep CSS and aria pattern verbatim, rendered from mergeSteps — plus a synthetic flatten stop built from flattened.blocks when nothing merged up, and a terminal stop that replaces the config <details>. The detail panel is the existing StepThrough + JsonDiff (its cumulative toggle is the "diff vs. base" here); the flatten stop's removals get a widget in the roadmap-026 benign-note pattern. Engine untouched.
