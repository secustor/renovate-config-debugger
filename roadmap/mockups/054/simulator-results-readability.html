Mockup 054 — Simulator results readability

047 staged the simulator into ask / answer / evidence, and it worked — the verdict is never buried. The remaining problem is inside the evidence: opening both drawers rebuilds the pre-047 wall, the same facts (the changed settings) repeat at three grains (ledger, per-rule "applied" lists, step diffs), and the step diff renders the whole 10,698-line config to show a handful of changed keys. This mock keeps 047's layers and proposes three different architectures for the evidence itself. Research notes at the bottom; full report in roadmap/2026-08-simulator-readability-research.md.

Mockup — app tokens from packages/app/src/index.css. Ledger threads, the rule-writer popover, and the step-jump return pill (variant A), the inspector rail (variant B), and the lens bar + elision rows (variant C) are interactive; the rest is static. Navigation model (both directions demoed above): the first drill level never navigates — a rule reference opens a popover with its clause evidence in place, so there is nothing to go back from (Esc / click-away closes). A real jump (the step link) opens the demoted replay and leaves a floating "↩ back to groupName" pill — the app's existing bottom-pill plane — which scrolls back and re-flashes the thread that sent you. In the real build both jumps also push the target into the URL fragment (the simStep convention), so the browser's Back button and share links work for free.

4 · Shared fixes — worth shipping under any variant

  • Digest diff. The step diff defaults to changed keys only (~ / + / −, old → new inline) with # N unchanged lines hidden — show; the full unified/side-by-side diff stays one click away. (Terraform's battle-tested shape for exactly this data.)
  • Name the override. A write a later rule clobbers is flagged wherever it appears — struck through with "overridden by packageRules[N] in step M" — and the winning key wears a 2 writers badge. Today the loss is silent.
  • Aligned ledgers. Every key value origin list shares its columns (key, value, provenance), so the value column has one edge instead of starting wherever each key ends.
  • Say "4 of 719" once. The verdict owns the count; drawers/lenses/rails reference it without restating it.
  • Demote chips in evidence. Full provenance chips stay on the verdict card; inside evidence layers the same fact is a colored dot with the chip on hover — all four matched rules sharing one source was worth 4 chips × 28 characters in the current UI.
  • Name the inert state. "Matched but changed nothing" (rule [0], ±0) is today only visible as a timeline delta; every variant above labels it, because an unexplained matched-rule-with-no-effect reads as a bug.

Research notes (condensed)

  • Two views, two questions. DevTools separates "what is the value" (Computed pane: winner only, expandable to the ordered cascade with losers struck through and jump-links to source) from "why" (Styles pane) — users default to the cheap answer and escalate on surprise. Variant A is this transplanted to a sequential last-writer-wins merge. developer.chrome.com/docs/devtools/css
  • Decisive subset, never a dump. IAM policy simulator, GCP Policy Troubleshooter, Skyhigh rule tracing and LaunchDarkly evaluation reasons all pre-compute which rules were causally relevant (typed reason codes, decisive-statement labels, three visual states for matched / evaluated-unmatched / skipped) — the viewer never infers relevance from a flat list. Variant B's rail grouping and the "matched but changed nothing" badge. docs.aws.amazon.com · cloud.google.com/policy-intelligence · launchdarkly.com/docs
  • Severity-driven expansion. GitHub Actions / Buildkite auto-expand only failed steps; default disclosure state derives from "is this abnormal", never from position. Variant C pre-expands the 4 matched rules and collapses the 715 no-matches to a counted row. docs.github.com · buildkite.com/docs
  • Elided-but-acknowledged. Terraform's # (12 unchanged attributes hidden) — collapse must render as a counted placeholder, or trust dies; and false-positive "changes" (plan noise) destroy diff scannability, so the digest must be precise about what genuinely changed. The digest diff everywhere above. developer.hashicorp.com/terraform
  • Sequence ⇒ index + one detail pane. Jaeger keeps the waterfall persistent as a spatial index with a single drill-down panel beside it; Compiler Explorer keeps the floor at two panes and makes depth opt-in with the whole layout in the URL — matching the app's fragment-only share convention. jaegertracing.io · github.com/compiler-explorer
  • Constraints carried over from 047's research: never gate the verdict; two disclosure levels max; every collapsed header keeps a computed count/preview; and the per-clause predicate-vs-evaluated evidence stays one interaction away — the persona study called it "the single most convincing screen". roadmap/2026-07-progressive-disclosure-research.md · roadmap/2026-07-persona-ux-study.md
